# Vision-ассистент (архив)

Отдельная подсистема, разработанная одногруппником параллельно с игровым ассистентом в рамках
командного курсового проекта 6-го семестра (ветка `cv-dev`). **К игровому ассистенту отношения
не имеет** и в его пайплайн не входит: ни один модуль из `api/`, `models/`, `main.py` и `tests/`
её не импортирует.

Раньше лежала в каталоге `backend/`, из-за чего выглядела как серверная часть проекта. Перенесена
сюда, чтобы не вводить в заблуждение.

## Что внутри

Ассистент, работающий поверх экрана, а не внутри игры:

| Файл | Назначение |
|---|---|
| `main.py` | Отдельное FastAPI-приложение, запускает оверлей отдельным процессом |
| `core/capture.py` | Захват экрана (dxcam) |
| `core/vision.py` | Анализ изображения |
| `core/voice.py` | Распознавание речи (faster-whisper) |
| `services/tts_service.py` | Синтез речи |
| `services/memory_service.py` | Долговременная память на ChromaDB + sentence-transformers |
| `services/hotkey_service.py` | Глобальные горячие клавиши (pynput) |
| `overlay/window.py` | Оверлей-окно на PyQt6 |

## Статус

Не запускается вместе с основным сервером и не поддерживается. Зависимости вынесены в
`requirements-vision.txt` (torch, PyQt6, faster-whisper, PyAudio, chromadb и прочее — установка
долгая и на Windows требует сборочных инструментов).

## Зачем сохранено

Тема дипломного проекта — мультимодальный интеллектуальный ассистент для игровых сред. Восприятие
состояния игры по экрану нужно там, где игра не отдаёт данные программно, а голосовой ввод и вывод
— второй модальный канал. Этот код может стать отправной точкой для соответствующих компонентов
диплома, поэтому удалять его нецелесообразно.

В курсовой работе 7-го семестра не используется.
