# Отличие от курсового проекта 6-го семестра

Материал для обоснования темы и для введения пояснительной записки.

## Что было сдано и остаётся

Курсовой проект 6-го семестра по требованиям кафедры — **интерфейс** интеллектуальной системы.
Он сделан и переиспользуется: мод Fabric для Minecraft 1.20.1 (~2000 строк), игровой чат,
оверлей-экран, телеметрия событий и состояния игрока, серверная часть на FastAPI с циклом
вызова инструментов и админкой.

Преемственность требуется прямо — раздел 28 руководства, — поэтому переиспользование интерфейса
не сокращение объёма, а выполнение требования.

## Чего не было вообще

Из трёх компонентов, которые 7-й семестр требует объединить в гибридную систему, в наличии был
один. Это не оценочное суждение, а проверяемый факт.

**Базы знаний не было.** `data/minecraft_catalog.json` — плоский список на 261 запись (из них
211 уникальных, 50 дублей) **без единой связи между сущностями**. Рецепты в
`minecraft_crafting_recipes.json` хранятся русскими строками («доска», «бревно»), не связанными
с идентификаторами предметов, без выходного количества. По этим данным нельзя ничего вывести —
только показать человеку картинку. Требование 4-го семестра «декларативные знания, задающие
сущности и связи между ними» не выполнялось.

**Решателя не было.** Вся «символьная» часть — это нечёткое сопоставление строк
(`SequenceMatcher`, список стоп-слов, стемминг по префиксам, захардкоженным вручную) плюс две
константы-лимита `MAX_ITEM_COUNT = 64` и `MAX_SUMMON_COUNT = 16` и регулярное выражение на
количество. Обрезание параметров — не логический вывод.

**Знание о мире жило внутри модели.** Показательна реализация `api/wiki.py`: не нашли рецепт в
рукописной базе — спрашиваем у языковой модели. То есть в роли базы знаний выступали веса
модели, со всеми вытекающими: галлюцинации идентификаторов, незнание версии игры, отсутствие
гарантий.

**Ничего не измерялось.** Ни размеченного набора, ни метрик, ни сквозных тестов.

## Что меняется

| | 6-й семестр | 7-й семестр |
|---|---|---|
| Знания о мире | 261 запись, связей нет | онтология RDF/OWL: 1174 рецепта, 1091 лут-таблица, 413 тегов, 1271 достижение, 2996 названий |
| Рецепты | русские строки, машинно непригодны | граф с идентификаторами, пригодный для вывода |
| Вывод | отсутствует | планировщик: обратный вывод по крафту, добыче и требованиям к инструменту, с учётом инвентаря |
| Проверки | две константы и регулярка | правила онтологии: запреты, прогрессия, режимы, с объяснением причины |
| Источник знаний | веса языковой модели | база знаний; модель только понимает речь и формулирует |
| Сопоставление названий | нечёткое совпадение строк | эмбеддинги, со старым вариантом как точкой отсчёта |
| Оценка качества | нет | золотой набор, метрики, сравнение трёх конфигураций |

## Почему это смена класса системы, а не улучшение

Сейчас система — **обёртка над языковой моделью со справочником для подстановки
идентификаторов**. Она не знает предметной области; знание подменяется моделью.

Становится — **гибридная система, где знание и гарантии вынесены наружу**, а модель отвечает
только за то, в чём она действительно сильна: понимание свободной речи и формулировки.

Разница проверяется одним запросом.

```
Сейчас:  «призови дракона края» → /summon minecraft:enderman
Станет:  «призови дракона края» → отказ: призыв боссов запрещён правилом
```

Эндермен появляется потому, что слово «края» нечётко совпало с алиасом «странника края».
Запрета на боссов не существует — есть лишь отсутствие записи в справочнике, и эта «защита»
не работает. После переработки запрет становится явным фактом базы знаний, который проверяет
решатель и умеет объяснить.

Второй пример — то, что сейчас невозможно в принципе:

```
Игрок: хочу алмазную кирку
    → не хватает 3 алмазов
    → алмазы добываются железной киркой и выше, ниже нулевой высоты
    → железной кирки нет, вот как её сделать из того, что есть
```

Для такого ответа нужны граф рецептов, лут-таблицы, требования к инструменту, состояние
инвентаря и рекурсивный вывод. Ни один из этих элементов в проекте 6-го семестра не
существует.

## Измеренная точка отсчёта

Прогон золотого набора на текущей системе (56 реплик, `eval/reports/`):

- совпало с разметкой — **53.6%**;
- небезопасных расхождений, когда система уверенно и молча делает не то, — **10.7%**;
- основные причины: распознавание намерения по списку из 15 ключевых слов не ловит «нужен
  хлеб» и «хочу стейк» (11 промахов), нечёткое сопоставление подменяет предмет (4 примера),
  необработанные словоформы (2).

Эти цифры зафиксированы **до** начала переработки, поэтому сравнение «до и после» в третьем
разделе записки будет честным, а не подогнанным.
