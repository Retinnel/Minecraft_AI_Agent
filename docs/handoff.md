## Договорённости

### Оформление записки

Проверяющие придираются к оформлению, поэтому эти правила обязательны. Образец — записка
6-го семестра `report/reference/KP6sem.pdf`. Текущая записка собрана в
`report/cource_report.pdf`; после правок исходников её пересобирают `sh report/build.sh`
и коммитят вместе с ними.

- **Жирным не выделяется ничего, кроме названий разделов.** Курсив не используется.
  В перечне условных обозначений не выделяется ничего (поэтому он набран абзацами,
  а не окружением `description`).
- **Ссылки на источники — в конце абзаца, вплотную к последнему слову, без пробела:**
  `…искусственном интеллекте\cite{X}.` Несколько работ в одном абзаце — одной ссылкой.
- **Подпись таблицы — над таблицей**, подпись рисунка — под рисунком.
- **О прошлом семестре в записке не пишется ничего.** Только то, что есть и должно быть.
  Обоснование отличия от 6-го семестра — в `docs/delta-from-previous.md`, для куратора.
- Введение — не длиннее 1,5–2 страниц.
- Список источников никто не проверяет; источники можно брать и из прошлой записки.
- Рисунки — средствами TikZ в `report/figures/`, схемы алгоритмов — по ГОСТ 19.701.
- Шаблон LaTeX от кафедры менять минимально; сделанные правки преамбулы помечены
  комментариями «Зачем:».

### Поведение системы

- **Никаких тихих исправлений.** Неоднозначно — переспросить; некорректно — отказать с
  объяснением. «Дай меч» → уточнение; «дай 0 алмазов» → отказ; «дай 1000 алмазов» →
  выдать 64, назвав число.
- **Запреты — явными правилами базы знаний**, а не отсутствием записи: «призови дракона
  края» → «знаю и не дам, потому что…», а не «не знаю такого».
- Задание выдаётся только после того, как решатель доказал его выполнимость.

### Работа с агентом

- Общение, комментарии в коде и сообщения коммитов — на русском; идентификаторы — на
  английском. Коммиты в стиле `feat(область): …` с объяснением причины в теле.
- Когда студент даёт время или говорит «делай всё до …», работать без остановок между
  задачами и отчитываться в конце.
- Для выбора между идеями студент любит короткие опросы с вариантами.
- Неочевидные решения и найденные проблемы называть прямо, с цифрами; не выдавать
  незавершённое за готовое.

## Что сделано

Этапы 0–4 из `PLAN.md`:

- **Оценочный контур** `eval/`: золотой набор 61 реплика, конфигурации A (только LLM),
  B (символьная), C (гибрид), повторные прогоны с медианой и разбросом, сводная таблица.
- **База знаний** `kb/`: онтология RDF/OWL из данных Minecraft 1.20.1 — 1522 сущности,
  1144 рецепта, 25 тыс. триплетов; рукописные слои запретов и разговорных названий.
- **Решатель** `solver/`: планировщик обратного вывода (покрывает 71% предметов игры,
  медиана 0,06 мс), развилки с отвергнутыми вариантами, валидатор с правом вето,
  проверка выполнимости заданий.
- **Резолвер** `resolver/`: сопоставление свободной речи с онтологией, трёхзначный ответ
  (найдено / неоднозначно / нет такого).
- **Конвейер** `orchestrator/` в живом игровом чате: модель извлекает намерение,
  решатель решает, модель формулирует ответ только по выходу решателя. Режимы, задания,
  продолжения диалога, переформулировка неизвестных названий.
- **Мод**: вкладка «План» в оверлее (клавиша O), переключатель режима.
- **Страница сравнения** `/compare` для защиты.
- **Записка**: введение, раздел 1, раздел 2 с четырьмя диаграммами (31 страница).

Главный результат на 61 реплике (openai/gpt-oss-120b, температура 0): гибрид — 57 из 61
в трёх прогонах (разброс 57–58), **ноль недопустимых действий во всех трёх**; только LLM —
62% и 21% недопустимых; символьная схема — 48% и 11%.

Что проверено и отклонено: векторный слой резолвера — близость не отделяет парафразы
от выдуманных названий (`eval/reports/2026-10-19-embedding-probe.md`).

## Развёртывание на новой машине

Нужны: Python 3.13, Git, JDK 17 (Temurin), MiKTeX или TeX Live с `cm-super`.

```bash
git clone https://github.com/Retinnel/Minecraft_AI_Agent.git "KP MC ASSISTANT"
cd "KP MC ASSISTANT"
git checkout llm-dev
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
```

**Ключи** — файл `.env` в корне, в репозитории его нет и быть не должно. Перенести вручную:

```
GROQ_API_KEY=...
OPENROUTER_API_KEY=...
DEEPSEEK_API=...
```

DeepSeek — платный, баланс около 10 $; это запасной провайдер (`deepseek-chat`), не основной.

Без ключей сервер работает, но чат отвечает «модель недоступна». Groq отвечает 403, если
включён VPN.

**Java для мода.** Системная `java` может быть другой версии; Gradle направляется на JDK 17
файлом `~/.gradle/gradle.properties` (пути — прямыми слэшами):

```
org.gradle.java.home=C:/Program Files/Eclipse Adoptium/jdk-17.<версия>-hotspot
```

Мод собирается первым: сборка скачивает jar клиента Minecraft, из которого строится база
знаний.

```bash
cd mod/minecraft-mod && ./gradlew.bat build && cd ../..
./.venv/Scripts/python.exe -m kb.fetch_locale
./.venv/Scripts/python.exe -m kb.extract
./.venv/Scripts/python.exe -m kb.build
./.venv/Scripts/python.exe -m pytest tests -q --ignore=tests/test_ui_smoke.py
```

Записка — `sh report/build.sh`, результат `report/cource_report.pdf`. Сервер —
`./.venv/Scripts/python.exe -m uvicorn main:app --port 8000`, клиент игры —
`cd mod/minecraft-mod && ./gradlew.bat runClient`.

## Подводные камни для агента

- В Windows-окружении этой машины инструмент Bash портил обратные слэши в heredoc и
  однострочниках: LaTeX и регулярные выражения Java приходили сломанными. Файлы с `\`
  создавать и править через Write/Edit, а не через `cat <<EOF` или `sed`.
- Отчёты `eval/reports/` называются по дате и перезаписываются в пределах дня: прогон,
  оборванный лимитом провайдера, затирает удачный. Перед коммитом проверять строку «Сбоев
  связи с моделью».
- Проверочные запросы к живому чату создают задания в `data/challenge_state.json` —
  после проверки отменять. Тесты обязаны подменять путь к этому файлу.
- Модели у провайдеров снимаются без предупреждения: если ответ «model does not exist»,
  смотреть список моделей провайдера и править `llm_config.json`.
